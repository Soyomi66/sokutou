# 設計メモ: 独自の推論エンジンの方式

> 実装を始める前（2026-11-10）に書いたメモです。数値と案はその時点のもので、そのあと作ったエンジンの結果は [results.md](results.md) にあります。文中の「本番」は作者の音声合成サーバーです。

Irodori-TTS v4.1-Small を公式の実装より速く合成する独自のエンジンについて、実装の方式を比べ、すすめる案をまとめました。対象は今の本番と同じ設定（RF 40 ステップ、independent の CFG を前半 20 ステップだけ、強さは文 3.0・caption 3.0・話者 5.0）で、GPU は RTX 6000 Ada です。目標は同じ GPU と同じ 48 文で speech.cpp より速く合成することです。エンジンはまだ作っていません。数値の詳しい測り方は [baseline.md](baseline.md) にあります。

計測日: 2026-11-10。公式の実装は音声合成サーバーと同じイメージ（今の `sokutou/official:7ed4374` と同じ中身。コミット 7ed4374、fp32）を、speech.cpp は v0.10.1（Vulkan、F16 の重み）を、どちらも GPU 0 で動かしました。

## すすめる案

2 段階で作ることをすすめます。

1. 1 段目は PyTorch で動くエンジンです。サンプリングのループを自前で持ち、DiT や ModernBERT などの計算には公式のモジュールをそのまま使います。40 ステップを CUDA Graph にまとめ、パディングと空の caption を外し、話者の条件をキャッシュし、AdaLN の係数を前もって計算します。読み間違いと声の近さが公式と同じくらいなら、DiT の行列積は TF32 で計算します。
2. 2 段目は DiT を C++/CUDA で自作することです。作るかどうかは 1 段目を測ってから決めます。

speech.cpp は同じ GPU と同じ 48 文で 1 文 0.394 秒（中央値）でした。公式のモジュールのまま、CUDA Graph にまとめてパディングを外し、TF32 を使うだけで 0.237 秒になり、speech.cpp を超えました。この値には電子透かしも入っています。1 段目の残りの変更を入れると、TF32 で約 0.19 秒、fp32 で約 0.34 秒になると見込んでいます。

速さをいちばん左右するのは、実装の言語ではなく行列積の精度です。この GPU は、計算を続けると電力の上限（約 300 W）に達し、クロックが 2.5 GHz から 1 GHz ほどに下がります。そのため、行列積だけを続けて回すと、fp32 は約 17〜22 TFLOPS しか出ません。TF32 にすると、3 つ分を通す行列積が約 2.4 倍速くなります。C++/CUDA で DiT を自作して上乗せできるのは、同じ精度で 1 文 0.02〜0.06 秒ほどと見込んでいます。

TF32 を使うと、出力は公式の実装と数値では一致しなくなります。そのため、数値で突き合わせる確認は fp32 で済ませ、TF32 は読み間違いと声の近さで確かめることをすすめます（[出力の確かめ方](#出力の確かめ方)）。fp32 のままでも、1 段目は中央値と短い文で speech.cpp を超える見込みですが、いちばん長い文では超えない見込みです（[決めてほしいこと](#決めてほしいこと)の 2）。

## speech.cpp と同じ条件での比較

48 文 × シード 1, 2 の 96 回の値です。どれも同じ `seconds` を渡し、同じ GPU 0 で測りました。

| 条件 | 行列積の精度 | 電子透かし | 中央値 | 90 パーセンタイル | 最大 | 15 字以下 | 25 字以上 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 公式の実装 | fp32 | あり | 0.775 秒 | 0.800 秒 | 0.928 秒 | 0.763 秒 | 0.786 秒 |
| CUDA Graph、パディングなし | fp32 | あり | 0.389 秒 | 0.469 秒 | 0.571 秒 | 0.284 秒 | 0.456 秒 |
| CUDA Graph、パディングなし、TF32 | TF32 | あり | 0.237 秒 | 0.264 秒 | 0.316 秒 | 0.203 秒 | 0.254 秒 |
| speech.cpp v0.10.1（Vulkan） | F16 の重み | なし | 0.394 秒 | 0.417 秒 | 0.439 秒 | 0.259 秒 | 0.411 秒 |

- fp32 のままでは、全体の中央値は speech.cpp と同じくらいです。15 字以下と 25 字以上に分けるとどちらも speech.cpp より遅く、90 パーセンタイルと最大も遅くなります。TF32 にすると、どの値でも speech.cpp より速くなります。
- 公式の実装と CUDA Graph の行は、合成から 24kHz への変換と前後の無音の切り落としまでを、コンテナの中で測りました。speech.cpp の行は同じマシンから HTTP で送って返ってくるまでの時間です（speech.cpp のログにある合成の時間は中央値 0.392 秒）。speech.cpp は 48kHz のまま返し、無音の切り落としもしません。
- 1 文ごとに 2 秒の間を空けて測っても（シード 1 の 48 回）、CUDA Graph、パディングなしは 0.376 秒、TF32 にしたときは 0.240 秒で、ほとんど変わりませんでした。
- 前の計測（別の 13 文 × シード 2、GPU 1）では、speech.cpp の読み間違い率は 1.1%、声の近さは 0.911 で、公式の実装は 0.9% と 0.903 でした。F16 の重みでも、読み間違いと声の近さは公式と同じくらいでした。

## 今の時間がどこにかかっているか

公式の実装の 1 文の合成時間は中央値 0.775 秒でした（48 文 × シード 2）。内訳は別の回（48 文 × シード 1）に区間ごとに測った中央値です。

| 段階 | 時間 |
| --- | --- |
| 条件のエンコード（ModernBERT と話者のエンコーダー） | 0.034 秒 |
| KV の準備 | 0.009 秒 |
| DiT の 40 ステップ（3 つ分を通す 20 回と、1 つ分を通す 20 回） | 0.70 秒 |
| 復号 | 0.016 秒 |
| 電子透かし | 0.007 秒 |

DiT を 1 回通すと、約 1,100 個のカーネルを起動します。GPU が計算している時間は、3 つ分を一度に通すときで 10.4 ミリ秒、1 つ分のときで 5.7 ミリ秒でした。一方、1 回にかかる時間はどちらも 17〜18 ミリ秒でした。残りの時間は、CPU がカーネルを起動し終えるのを GPU が待っている時間です。前の計測で、一度に通す数やトークン数を変えても 1 ステップの時間が変わらなかったのは、このためと考えられます。

そこで、公式のモジュールのまま、KV の準備と 40 ステップを 1 つの CUDA Graph に記録して再生しました。1 文の合成時間は 0.449 秒になり（48 文 × シード 2）、出力は公式の実装と同じでした（潜在変数の誤差 0）。

CUDA Graph を使っても、GPU の計算時間は残ります。その中には、なくせる計算、まとめられる小さな処理、遅い fp32 の行列積が含まれています。

- 文は 256 トークンまでパディングしてから通しています。48 文の有効なトークンは 4〜18 個でした。
- caption は空ですが、512 トークン分を ModernBERT に通し、DiT の attention にも入れています。マスクはすべて無効なので、結果には効いていません。
- AdaLN（時刻から各層の係数を作る計算）は、時刻だけで決まります。40 ステップの時刻は毎回同じなのに、1 回通すごとに 144 回の小さな行列の計算をしています。
- 話者の条件（参照音声から作る 50 トークン）は声ごとに同じですが、文ごとに計算しています。
- カーネルは 1 層あたり約 90 個です。そのうち大きな行列積は 8 個、attention は 1 個です。残りは AdaLN の小さな行列の計算（12 個）と、正規化、RoPE、attention の出力に掛けるゲートなどの小さな処理です。
- fp32 の行列積は、行列積だけを続けて回すと 3 つ分で 1 回 8.3 ミリ秒（17.3 TFLOPS）でした。行の数を 4096 に増やしても約 19 TFLOPS で、行の数が少ないことは主な理由ではありませんでした。行列積を測っているあいだ（fp32、TF32、BF16 を続けて測りました）、GPU は電力の上限に達し、SM のクロックは中央値 1,035 MHz でした。

## 速くするところ

次の 5 つは、どれも数学的には公式と同じ計算です。違いは丸め誤差だけです。

1. パディングした文のトークンと空の caption を、attention と KV から外します。空の caption は ModernBERT にも通しません。
2. AdaLN の係数を、40 ステップ分まとめて読み込みのときに計算しておきます。
3. 話者の条件と、その KV の射影を、声ごとに一度だけ計算しておきます。
4. 40 ステップと CFG の合成を、1 つの CUDA Graph にまとめます。
5. 小さな処理を、1 層あたり数個のカーネルにまとめます。これには C++/CUDA が要ります（2 段目）。

1 と 4 は CUDA Graph の基準で試し、1 文の合成時間は 0.449 秒から 0.389 秒になりました（空の caption を ModernBERT に通す処理は、このときは残しています）。出力の差は公式の実装を CPU と GPU で動かしたときの差より小さくなりました。24kHz の出力の SNR は、パディングを外したときが 67〜68 dB、公式の実装の CPU と GPU のあいだが 62〜63 dB です。

このほかに、行列積の精度を下げる変更があります。これは公式と同じ計算ではありません。

6. 行列積を TF32 で計算します（入力の仮数を 10 ビットに丸めて、Tensor Core で計算します）。CUDA Graph、パディングなしに足すと、0.389 秒から 0.237 秒になりました。
7. 重みを BF16 にします。行列積だけを測ると、TF32 よりさらに 2 倍ほど速くなりました。BF16 は 1 文の合成では試していません。

## 見込み

| | fp32 | TF32 | BF16 |
| --- | --- | --- | --- |
| CUDA Graph、パディングなし（測った値。1 と 4） | 0.389 秒 | 0.237 秒 | 測っていない |
| 1 段目（見積もり。1〜4） | 約 0.34 秒 | 約 0.19 秒 | 見積もっていない |
| 2 段目（見積もり。1〜5、C++/CUDA の DiT） | 約 0.28〜0.29 秒 | 約 0.16〜0.17 秒 | 約 0.11〜0.12 秒 |
| speech.cpp（測った値） | | | F16 の重みで 0.394 秒 |

見積もりは測った値から差し引いて出しました。

- 1 段目では、条件のエンコードが 0.034 秒から約 0.012 秒になります。有効なトークンだけで文をエンコードすると 0.012 秒でした（PyTorch のまま測った値）。話者の条件はキャッシュし、空の caption は通しません。AdaLN の前計算で、さらに約 0.029 秒減ります（プロファイルでは、AdaLN の小さな行列の計算が 3 つ分で 1 回 0.94 ミリ秒、1 つ分で 0.5 ミリ秒）。合わせて約 0.05 秒を、測った値から引きました。
- 2 段目の見積もりは DiT の時間を行列積とそれ以外に分けて出しました。CUDA Graph、パディングなしの DiT の時間（`sample_rf` から条件のエンコードを引いた値。KV の準備を含む）は、fp32 で 0.322 秒、TF32 で 0.175 秒です。行列積だけを続けて回した速さから計算すると、40 ステップの行列積は fp32 で 0.224 秒、TF32 で 0.104 秒です。残りは fp32 で約 0.10 秒、TF32 で約 0.07 秒で、そこから AdaLN の分（約 0.029 秒）を引くと、fp32 で約 0.07 秒、TF32 で約 0.04 秒になります。C++/CUDA で小さな処理をまとめると、attention を含めて 40 ステップで 0.012〜0.024 秒になると仮定しました（1 ステップ 0.3〜0.6 ミリ秒）。
- BF16 の見積もりは行列積だけの速さ（3 つ分で 1.7 ミリ秒、1 つ分で 1.0 ミリ秒）に、同じ仮定の残りと、復号・電子透かし・後処理（約 0.03 秒）、文のエンコード（0.012 秒）を足した値です。

## 方式の比較

| 方式 | 速さの見込み | 移植の手間 | Irodori の更新への追い付き | ライセンス |
| --- | --- | --- | --- | --- |
| PyTorch で動く独自のエンジン（1 段目） | 1 文約 0.19 秒（TF32、見積もり）。公式のモジュールのまま CUDA Graph、パディングなし、TF32 で 0.237 秒（測った値） | 小さい。ループと前計算だけを書き、重い計算は公式のモジュールを呼ぶ | 追い付きやすい。公式のモジュールをそのまま使う | 公式の実装と同じ |
| C++/CUDA（cuBLAS、自作のカーネル、CUDA Graph） | 1 段目より同じ精度で 1 文 0.02〜0.06 秒速い見込み。BF16 なら約 0.11〜0.12 秒（見積もり） | 大きい。DiT だけなら 12 層の同じ構造で、範囲は限られる | 重みだけの更新は、名前で読み込めばそのまま使える。構造が変わったら手で移植する | 自分のコード。cuBLAS は CUDA Toolkit の再配布の条件に従う |
| ggml の CUDA 版（speech.cpp を元にする） | speech.cpp の Vulkan 版は 0.394 秒（F16、測った値）。CUDA 版は測っていない | speech.cpp を CUDA でビルドできれば小さい。電子透かしは足す必要がある | speech.cpp の更新を待つか、自分で直す | speech.cpp は MIT。ggml のライセンスはこのメモでは確かめていない |
| TensorRT（公式のモジュールを ONNX にして変換） | 小さな処理は自動でまとめられる。fp32 の attention をどこまでまとめるかは確かめていない | 中くらい。複素数の RoPE や真偽値のマスクを、ONNX にできる形に書き換える必要がある | 公式の PyTorch のコードから変換し直せるので、追い付きやすい | NVIDIA の独自のライセンス（条件は確かめていない）。このマシンには入っていない |
| Rust（candle などと cuBLAS） | C++/CUDA と同じくらいまで出せるが、小さな処理をまとめるには自作のカーネルが要る | 大きい。CUDA Graph や自作のカーネルの道具が C++ より少ない | C++/CUDA と同じ | candle のライセンスはこのメモでは確かめていない |

2 段階をすすめる理由は 3 つです。

- 速さを大きく変えるのは、CPU の待ちをなくすこと（CUDA Graph）、要らない計算を外すこと、行列積の精度です。この 3 つは PyTorch のままでもでき、それだけで speech.cpp を超えました。
- 1 段目は手間が小さく、公式のモジュールを使うので Irodori の更新にも追い付きやすくなります。エンコード、復号、電子透かしを動かす Python のサーバーは、2 段目でも要ります。
- 2 段目の C++/CUDA は、1 段目でまだ足りないときに、小さな処理をまとめる手段として残します。方式を比べた中では、カーネルを自分で書けて、段階ごとの SNR でどの層がずれたかまで確かめられる C++/CUDA がいちばん向いています。

## すすめる案の構成

```
HTTP サーバー（Python。POST /v1/audio/speech、X-Synthesis-Seconds は今と同じ）
  ├─ 文字の変換（公式のトークナイザー）
  ├─ 文の条件のエンコード（公式の ModernBERT。有効なトークンだけ通す）
  ├─ 話者の条件（公式の話者のエンコーダー。声ごとに起動のときに一度だけ）
  ├─ DiT の 40 ステップと CFG
  │     1 段目: 公式のモジュールを 1 つの CUDA Graph で（TF32、AdaLN は前計算）
  │     2 段目: C++/CUDA のエンジンに置き換える（必要なら）
  ├─ 復号（公式の DACVAE）
  └─ 電子透かし（公式の SilentCipher）と 24kHz への変換、前後の無音の切り落とし
```

作る順番は次のとおりです。

1. HTTP サーバーとサンプリングのループを作ります（1〜4 の変更）。fp32 のまま、保存した参照と段階ごとの SNR で比べます。
2. DiT の行列積を TF32 にします。48 文で、速さ、読み間違い、声の近さを、公式の実装と speech.cpp と比べます。電子透かしが検出できることも確かめます。
3. 本番への組み込みを相談します。
4. まだ速くしたいときは、2 段目（C++/CUDA の DiT）に進みます。最初は fp32 で作って保存した参照と比べ、そのあと TF32 や BF16 にします。

電子透かしは外してよいことになりました（2026-11-11、利用者の判断）。公式の README とモデルカードには、透かしを入れることを求める記述はありません。モデルカードが禁じているのは、同意のない声のまねと、人をだます目的の合成音声で、透かしの有無にかかわらず守ります。このメモの速さの値は、どれも透かしを入れた値です。

## 出力の確かめ方

fp32 の段では保存した参照（`runs/ref/`）と、エンジンの出力を段階ごとに SNR で比べます（`tools/snr.py`）。合格の目安は公式の実装を CPU で動かしたときの差（下限の目安）をもとに決めました。

| 比べるもの | 目安 | CPU と GPU の差 |
| --- | --- | --- |
| ステップごとに参照の x を入れたときの v（CFG の 3 つ分） | 110 dB 以上 | 119 dB |
| 最初のノイズから通したときの最後の潜在変数 | 85 dB 以上 | 85〜97 dB |
| 24kHz の最終の出力（復号は公式の処理） | 60 dB 以上 | 62〜63 dB |

24kHz の出力の差は復号の段で大きくなります。GPU の復号は cuDNN の畳み込みに TF32 を使っている（イメージの既定）ので、入力のわずかな差が出力に大きく出ると考えています。

TF32 にすると、24kHz の出力の SNR は最小 14.5 dB・中央値 34.3 dB でした。CPU と GPU の差よりずっと大きく、波形がはっきり変わります。そのため TF32 の段は SNR ではなく、読み間違い（faster-whisper medium の書き起こし）と声の近さ（wavlm-base-plus-sv）で、公式の実装と speech.cpp と比べます。測り方は作者の前の計測と同じにします。

本番では、バックエンドがシードを送っていないので、文ごとに乱数のシードが変わります。エンジンは自前の乱数でノイズを作り、確かめるときは保存したノイズを入力として渡すことをすすめます。公式の実装と同じシードで同じ音声を出すには、torch の CUDA の乱数を再現する必要があります。1 段目は公式と同じ乱数を使えるので、この問題は 2 段目で起きます。

## 決めてほしいこと

1. 方式。すすめる案は 2 段階です。1 段目は PyTorch で動くエンジンで、C++/CUDA の DiT は 1 段目を測ってから決めます。
2. 精度。案は 2 つです。
   - fp32 のまま: 公式の実装と数値で突き合わせられます。1 段目の見積もりは、中央値が約 0.34 秒（speech.cpp は 0.394 秒）、15 字以下が約 0.23 秒（同 0.259 秒）です。25 字以上（約 0.41 秒）と 90 パーセンタイル（約 0.42 秒）は speech.cpp と同じくらいで、最大（約 0.52 秒）は speech.cpp（0.439 秒）より遅くなります。見積もりは、測った値の各列から 1 段目の分（約 0.05 秒）を引いたものです。
   - TF32: 1 段目の変更を入れる前から、どの値でも speech.cpp を超えました（測った値。最大 0.316 秒）。出力は公式の実装と数値では一致しなくなり、読み間違いと声の近さはまだ測っていません。

   すすめる案は、fp32 で作って数値で確かめたあと、TF32 の読み間違いと声の近さを測り、公式と同じくらいなら TF32 を使うことです。
3. 乱数。すすめる案は、公式と同じシードで同じ音声を出すことは求めず、確かめるときは保存したノイズを渡すことです。
4. MF 版（v4.1-Small-MF）への対応。すすめる案は、40 ステップのエンジンができてから決めることです。コードを読んだ範囲では、MF 版は時刻の差（delta_t）の条件が 1 つ加わり、ステップの進め方が違います。

## 確かめていないこと
